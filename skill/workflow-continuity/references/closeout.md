# Closeout and Continuation Handoff

Use for a selected family that actually owes durable documentation or a release handoff. Small local work without that obligation does not need a new finalization task or artifact.

1. Extract delivered behavior, impact, selected acceptance/proof layer and protected exclusions. Read relevant completed and pending work while evidence is still available; task completion alone is not semantic proof.
2. Reconcile the fitting owners by role: design for selected behavior/contracts; overview for current capability/use; changelog for material version/history; execution records for results, pending obligations and resume order. Preserve reachable historical evidence rather than rewriting it into a final-only success story.
3. Update only affected owners and exact references at a natural settled work boundary. Do not interrupt every check to synchronize all documents or wait until all unrelated work is done. Material design/approval prerequisites still precede dependent implementation.
4. Give the existing finalization owner exact changes, commands/scenarios, source/environment bindings, reached results, limitations and required remaining proof before the selected family closes. A report or queued message is not receiver acceptance; use supported receipt evidence if handoff acceptance is required.
5. Verify changed versions, parent/child references, links and pending/completed dispositions. For publication, bind the selected source commit, immutable tag, release record and public payload separately; never claim those operations from prepared files or a task status.
6. Close independently satisfied work at its actual gate. Keep explicitly required unavailable terminal proof blocked with its target, prerequisite, expected observable result and meaningful resume trigger. Optional live observations and successor proposals remain unselected rather than disguised as blockers or ordered tasks.

Report delivered behavior first, matching proof and its scope, material unfinished work with reason, and actual next state. Do not infer deployment, session reload, stability, lossless migration or measured benefit from source/release parity.
