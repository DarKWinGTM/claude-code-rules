## 1.0 - Evidence-Led Code Design (2026-11-14)

- Introduce an on-demand procedure for concrete caller/contracts, responsibility/knowledge/dependency boundaries, semantic reuse, representation/computation lifecycles and simpler complete alternatives.
- Keep cohesive code local and preserve justified duplication, projections, immutable history, security, freshness, isolation and recovery. No LOC/file quotas, automatic abstraction/cache/pipeline or refactor permission is added.
- Separate functional, structural and performance proof; research supports criteria, not a universal layout or measured local benefit. The local design owns checked source rationale and citations, not a mandatory runtime research step.
- Use the existing library test owner and bounded paired interpretation. Installation/publication outcomes belong to their execution receipt; this history does not infer adoption or model effectiveness from source authoring.
