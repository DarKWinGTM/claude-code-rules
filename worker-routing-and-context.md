## Rule Statement

**Core Principle: Main owns source implementation, synthesis and final proof. Narrow work to the locked decision first; delegate only for clear context/filtering/parallel/specialist net benefit using the smallest dependency-fitting topology. Workers supply bounded evidence, not authority, recursive work or review ritual.**

## Intent and Net-benefit Gate

Classify only enough to route: behavior/governance, lookup, diagnosis, implementation, review/audit, plan/design, coordination or explanation. AI/RULES questions stay behavior-first; logs/paths/snippets/handoffs are evidence, not inspection permission. Diagnose before edits; re-anchor corrected intent before exploration under [execution](execution-and-goal-frame.md).

Main/direct fits source/integration, bounded known files, tight sequential/interactive low-output work, high overlap, unavailable workers or explicit direction. File count, breadth and non-triviality alone earn no delegation. Narrow research/search/test/log/build/review to decision-changing evidence first.

[safe-io.md](safe-io.md) detects remaining bursts; this owner routes. Dispatch only when context/noise filtering, real parallelism, independent evidence or specialization outweighs brief/handoff/leader-check cost. Prefer equally reliable cheaper direct work. Route a beneficial remaining burst before more raw intake, or record a narrow direct reason; skipping blocks broad sync/no-drift/closeout claims. No exception ceremony once narrowing removes the burst.

Review also needs unresolved material risk/claim, realistic failure, smallest anchors, evidence threshold and accept/fix/block decision. Availability/reassurance earns no review; [execution](execution-and-goal-frame.md) owns admission/closure. Leave optional style/cleanup unselected.

## Topology and Invocation

| Work shape | Smallest useful topology |
|---|---|
| source/high-overlap/interactive integration | direct context-rich Main |
| one independent evidence/diagnosis/review/test axis | scout / `Scout preset`: one read-only standalone digest |
| independent analysis/review axes | fan-out/fan-in / `Compare preset`: concurrent standalone lanes, shared rubric |
| independent test/metrics/matrix cells | `Verification preset`: parallel lanes by real failure/platform/config/scenario dimension |
| evidence before correction | `Audit + Repair preset`: read-only audit, then Main source fix or exact permitted doc/test lane |
| dependent fixtures/state/workflow/messaging | coordinated swarm / `Coordinated swarm preset`: official Team only if standalone cannot coordinate safely |

Presets do not justify Team escalation. Selected delegation must actually invoke/fan in, not describe lanes. Launch independent lanes together; keep related failures together until their shared cause is discriminated. No shared-state parallel mutation without isolation or sequencing.

Team requires real dependencies/messaging/staged fixtures/durable handoff, not worker count—even three lanes. Use one coordinated Team with distinct roles/tasks, visible dependencies and targeted handoffs. Source stays Main-owned unless explicit stronger user/project authority selects otherwise.

A `teammate`/`Agent Team`/team-workflow ban need not ban standalone `Agent(...)`, `Explore(...)` or read-only support. An all-agent ban means direct work; mention it only when material. Ask substantive scope/access/artifact/approval questions, not internal routing menus.

## One Lane Brief and Permission Boundary

Bind served objective/goal-candidate, decision, authority, raw-versus-analyzed need, independence/overlap, availability and user restrictions. A self-contained brief names:
- bounded role and why separate context helps
- checked/excluded scope and exact allowed artifacts/anchors
- write permission: `none`, `governed-doc-only` or `test-only`
- actions/stop gates and shared rubric for parallel lanes
- filtered result/leader anchors and decision informed

Research/diagnosis/source investigation/audits/reviews default read-only. Exceptional edit lanes need exact non-overlapping governed-doc sections or test-only artifacts. Active Rule/Product source, README, config/integration/install, git/tags/releases and final integration stay Main-owned. No unrequested plans/specs/phases/Patches/directories, alternate architecture, history/file deletion, relocation, status promotion or authority changes. Preserve meaning/history/references and source/test separation. Ambiguous owner/scope/test relevance/history/safety returns a blocker. Main inspects every permitted edit before claims.

Review briefs bind risk/failure/threshold and `blocker`, `bounded correction` or `no material finding`. Research briefs bind decision/topic/source trust and bounded query refinement. Helpers never own Goal/route/task boundary/completion; [phase-todo-artifact.md](phase-todo-artifact.md) admits tasks.

## Standing-role Lifecycle

Check smallest useful coordination state before reuse/spawn/respawn/shutdown/duplicate claims. Names represent stable responsibilities, not phase/task IDs. Reuse/steer active/recent aligned roles; new roles need distinct simultaneous scope, explicit separate lane or evidenced unavailable/missing role—not phase/retry habit.

Audit fields: `requested_role`, `objective`, `checked_scope`, `observed_state`, `role_owner`, `objective_alignment`, `decision`, `reason`. States: `active`, `recent`, `stale`, `missing`, `unavailable`, `not found in checked scope`.

| Checked state | Decision |
|---|---|
| active/recent, same role/objective or next phase | reuse/steer |
| same role, different objective | distinct only with explicit lane boundary |
| stale/missing | verify before active-duplicate/safe-absence claim |
| unavailable | require enabling state/input/authorization before needed respawn |
| not found in checked scope | scoped nonfinding; spawn only if scope sufficient |

UI/tmux residue, stale boards and memory prove neither overlap, absence nor cleanup readiness. Safety owns `AGENT_TEAM_DUPLICATE_OR_STALE_TEAMMATE_PRESENCE` classification/no unchanged retry; this audit chooses reuse/steer/wait/partition/evidenced respawn. Harness completion arrives by notification, not short polling. Availability grants no assignment/shutdown permission.

## Filtered Handoff and Main Verification

Lead with outcome, checked/excluded scope, evidence/strength, uncertainty/conflicts, decisive anchors and next matching check/stop. Explain what ran, checked and informed; no raw dumps/generic new-work list. Clarification/reread churn calls for tighter briefs/topology, not more intake.

- research: query families, source authority/freshness/specificity, conflicts, implications and leader checks
- tests/metrics: exact command/scenario, environment/matrix cell, terminal result/failure, coverage limit/rerun need
- permitted repairs: changed anchors, preservation, checks and unresolved risks
- examples: separate observed shape, extracted doctrine, selected target and proved equivalence; retain partial limits, never present stricter recommendations as observed facts

Main resolves conflicts from source, verifies decisive anchors/every edit, applies source corrections and owns evidence/acceptance. Do not reread all evidence without a decision-changing reason. Scope Lock admits required same-outcome corrections, exposes blockers/approval and leaves unrelated improvements unselected.

After correction use affected-anchor and matching regression/architecture/security/migration/data/external-contract proof, not broad re-audit. Re-review only for changed owner/authority/contract/security/lifecycle, failed proof, contrary evidence, expanded scope or persisting uncertainty. Another lens needs distinct unresolved risk, not availability. Once answered and checks pass, fan in/close.

## Research, Mechanisms and Specialists

Broad external/roadmap/phase-matrix/design/provider research starts with the decision evidence can change. Narrow/stop at sufficiency; split useful independent axes before raw flood. Refine queries within scope; [external trust](external-verification-and-source-trust.md) evaluates authority/conflicts, not hit count.

Before coordination claims classify the checked mechanism: board stores state; hook reacts locally; injected context informs prompts; tmux transports text, not semantic acceptance; recall/memsearch retrieves context, not current truth; official Team and plugin/MCP provide checked/documented capabilities only. Unavailable stays unresolved. Desired behavior proves no delivery/mutation/authority. Plugin/shared-board grammar stays outside Main unless selected; [safety](action-safety.md) owns runtime deltas.

After routing, choose capability fit: visible user custom agents in `~/.claude/agents/` when clearly best, then project/built-in/plugin specialist, otherwise generic/direct. Existence earns no delegation/Team; reuse roles, never invent unavailable agents.

[Document owners](document-governance.md)/[integrity](document-integrity.md) settle authority/density/sharding/preservation/repair safety before routing. [Evidence](evidence-discipline.md) keeps worker/context output subordinate to checked proof.
