## What Changed

The existing analysis intake can select daily shards strictly older than a supplied date boundary. The analysis surface reports the first historical window's exact days and next-older boundary when the historical-default scope and trace-source policy permit it. One explicit request for different topics can use that boundary for a single supplemental scan through the existing bounded `intake → signals → present` path, generating a distinct candidate set.

The supplemental pass preserves the existing shard, record, character, byte, and source-policy limits; refuses explicitly/configurationally narrowed scope and source policies without `trace_evidence`; and reports the boundary, checked days, attempt/use status, intake status, and blocked reason. All new candidates retain the Phase075 trace-entailment, active-RULES novelty, completed-work novelty, semantic deduplication, and fail-closed gates. Rejected candidates cannot be rescued or reworded into the new set.

## Scope and Limits

No public slash command, evidence class, persistent continuation state, automatic search loop, write path, Main RULES mutation, external research, user-corpus scan, installation/cache change, settings change, or publication is added. An empty or ineligible supplemental window proves nothing about the remaining corpus.

Phase075 remains the completed eligibility baseline; this is a separate Phase076 extension of the same analysis flow. Package `0.9.36` is an uninstalled source candidate. Immutable package `0.9.31` remains latest published.
