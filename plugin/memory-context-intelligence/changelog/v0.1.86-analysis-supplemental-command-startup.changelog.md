## What Changed

The conditional supplemental-search command in `skills/analysis/SKILL.md` is now an ordinary `bash` code fence, not an executable context-injection fence. Startup injects only the initial `analysis-surface` command. After an explicit request for more/different topics and successful scope checks, the caller substitutes the actual `YYYY-MM-DD` value from `analysis_window.next_older_than_day` and invokes the supplemental template through its shell tool.

The initial wrapper, strict date parser, one bounded older-window policy, explicit config carry-forward, Phase075 eligibility and Phase077 parallel discovery remain unchanged. Manifest and all three public skill versions align at `0.9.38`; [the topic-flow design](../design/02-topic-list-and-choice-flow.design.md) owns the preprocessing boundary.

## Confirmed Failure and Cause

The user supplied two failed plain slash invocations showing the literal `<analysis_window.next_older_than_day>` passed to the CLI. Source and installed `0.9.37` skills both contained the second executable fence. Running that exact block reproduced exit 2 and `day must use YYYY-MM-DD format` before intake.

[Claude Code dynamic-context documentation](https://code.claude.com/docs/en/slash-commands#inject-dynamic-context) confirms that shell injections run before skill instructions reach Claude. Conditional prose therefore could not defer the supplemental command or substitute the payload field. Existing source tests checked that supplemental instructions existed but did not check the startup execution boundary; earlier plugin validation and byte parity did not prove successful slash invocation.
